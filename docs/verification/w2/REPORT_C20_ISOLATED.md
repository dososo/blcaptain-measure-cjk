- **codex**：使用临时的 `HOME` 和 `CODEX_HOME`。凭证是指向原文件的符号链接，没有复制，也没有读取内容。模型和推理强度从用户的 `config.toml` 读出后显式传入：gpt-6-astra，high。
- **claude**：`--safe-mode`、`--no-session-persistence`、`--output-format json`。实际使用的模型是 claude-opus-5-5。

## 4. 更正（回应 AUDIT_W2_C20，结论「有条件达标」）

1. **v1 的 claude 隔离基线并非没有任何 skill。**
   - 执行方在复核之后实测：`--safe-mode` 下，claude 的内置 skill（如 `artifact-design`、`dataviz`）仍然可用。
   - 之前说「`--safe-mode` 关闭 skills」只对用户 skill 成立。
   - 修正：v2 对照组加上 `--disable-slash-commands`，实测可用 skill 为「无」。
2. **v1 的 codex 隔离组只带过去了模型和推理强度**，其余顶层配置都用了默认值（W2-02）。
   - 审批和沙箱在两组里本来一致（`never`、`workspace-write`，已核对日志）。
   - 「patch rejected」次数（6 比 2）和平均用时（174 秒比 91 秒）的差异原因待确认。
   - 修正：v2 按白名单把模型、推理强度、审批、沙箱、人设、服务档位等顶层配置对齐到用户环境。
3. **撤回 T07 的归因。** 用户全局 CLAUDE.md 里没有字距规则，「T07 从 0 页升到 4 页和 CLAUDE.md 的偏好一致」这句话没有依据，撤回。T03 的归因（CLAUDE.md 偏好「」）仍然有依据。
4. **claude 用户环境组的模型没有记录**，两组模型可能不同。用户环境组的日志里拿不到模型名，无法补记，这一点写进局限。
5. **北极星实验方案更正。**
   - 原计划「实验组也用 `--safe-mode`、只额外加载 measure」不可行：执行方实测，`--safe-mode` 下 `--plugin-dir` 加载不了 measure；改用 `CLAUDE_CONFIG_DIR` 会导致「未登录」，重新登录需要用户本人操作。
   - 新方案：
     - **claude**：两组都用 `--safe-mode --disable-slash-commands`；实验组用 `--append-system-prompt-file` 注入 measure 的 SKILL.md 和参考文件。
     - **codex**：实验组把 measure 放进临时 `HOME/.agents/skills/`。
   - 注意：claude 实验组是「把 skill 内容当系统提示」，不经过真实的 skill 触发机制，测的是内容本身的效果。
6. **W2-06**：codex 凭证用符号链接指回原文件。如果 codex 刷新 token 时把链接替换成本地副本，原文件就不会更新，可能导致用户的登录失效。这次运行期间原文件没有被改动（审计方已核对）。之后如果还要用这个办法，运行结束后检查一次原文件。
7. **v1 结果保留不删**：`bench/runs/2026-W2-baseline-isolated-*`。v2 跑完后，北极星的对照组以 v2 为准。

## 5. 对照组 v2 的结果（2026-10-25）

**v2 的做法：**
- claude：`--safe-mode --disable-slash-commands`，可用 skill 实测为「无」；
- codex：临时 `HOME` 和 `CODEX_HOME`，顶层配置按白名单与用户环境对齐。

**隔离检查：**
- 60 份日志里没有出现用户目录路径，也没有读取过 SKILL.md；
- `~/.claude/projects` 没有新增会话目录；
- codex 凭证文件的修改时间和运行前一样（1792916128），仍是普通文件，没有被替换（W2-06）。

**三组对比**（同一版规则；零 error 按产出页面计）：

| agent | 组 | 零 error | 排除 T02/T04 后零 error | 平均用时 | patch rejected | 各规则命中的页面数（error） |
|---|---|---|---|---|---|---|
| codex | 用户环境 | 0/30 | 4/30 | 106 s | 2 | T02 30、T04 30、T11 25、T07 14、T13 7、T03 4、T08 1、T06 1 |
| codex | 隔离 v1 | 0/30 | 2/30 | 244 s | 6 | T02 30、T04 30、T11 25、T07 17、T03 4、T13 4、T06 4 |
| codex | **隔离 v2** | 0/30 | **4/30** | 130 s | 13 | T02 30、T04 30、T11 25、T07 15、T13 7、T03 4、T06 2、T08 1 |
| claude-code | 用户环境 | 0/30 | 18/30 | 73 s | 0 | T02 30、T04 30、T03 11、T11 2、T13 1、T08 1 |
| claude-code | 隔离 v1 | 0/30 | 14/30 | 69 s | 0 | T02 30、T04 30、T03 7、T13 4、T07 4、T11 2、T08 1、T06 1 |
| claude-code | **隔离 v2** | 0/30 | **18/30** | 70 s | 0 | T02 30、T04 30、T03 7、T11 2、T08 2、T13 2、T07 1 |

**解读：**
1. **v2 和用户环境的数字几乎一样**：排除 T02/T04 后的零 error 页面，codex 是 4 比 4，claude 是 18 比 18。v1 和 v2 的区别在于是否对齐配置、是否关闭内置 skill，v1 的数字更低。**这只是相关观察，不是因果结论**：每条提示词只跑了一次，同样的条件重跑，数字也可能有 2 到 4 页的波动（AUDIT_W2_C20_r2 R2-02）。
   - codex 还有两个配置节没有对齐：`features` 和 `shell_environment_policy`，两组都用的是隔离环境里的默认值。它们是否影响结果，没有验证。
2. **唯一比较稳定的差异是 claude 的 T03**：用户环境 11 页，两个隔离组都是 7 页。方向和用户全局 CLAUDE.md 偏好「」一致；本项目的默认配置按 GB/T 15834 用 “”。
3. **codex v2 的「patch rejected」是 13 次，比 v1 和用户环境都多。** 审计方从日志里找到一个比较可能的原因（R2-08，推测）：macOS 上 `/var` 是 `/private/var` 的符号链接，agent 用 `pwd` 给出的 `/private/var/...` 路径写文件时，被按字面比较的沙箱判成了越界，换成 `/var/...` 重试后成功。脚本已改为先把工作目录转成真实路径再传给 `-C`，下一次运行时验证。 30 页都正常产出了，所以这不影响页面质量的统计，但说明隔离环境下 codex 写文件的路径和用户环境不完全一样。
4. **每条提示词只跑了一次，没有方差估计**，上面的差异都不能当成因果结论。
5. **北极星的对照组以 v2 为准。** 第 4 节第 5 条的实验组方案有缺陷（R2-01），已修订为 `docs/verification/w2/NORTH_STAR_PLAN.md`，等用户确认。
6. **「可用 skill 为『无』」的探测记录**：`docs/verification/w2/evidence/claude-skill-probe.log`（R2-04）。
