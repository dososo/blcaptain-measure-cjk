logq 快速上手

logq 是一个开源的日志查询工具。它能直接在本地或远程服务器的日志文件里按条件搜索、实时跟踪和做简单统计，不需要先把日志导入数据库。

  • 当前版本 v2.3.0
  • MIT 许可证
  • 支持 macOS、Linux、Windows

1安装

logq 是一个单独的可执行文件，没有运行时依赖。选一种适合你系统的方式安装即可。

$ brew install logq
$ curl -fsSL https://logq.dev/install.sh | sh
$ cargo install logq --locked
> winget install logq.logq

装好后检查一下版本号，能看到输出就说明安装成功：

$ logq --version
logq 2.3.0

用安装脚本时，建议先打开脚本看一遍内容再执行。脚本默认装到 ~/.local/bin，请确认这个目录在你的 PATH 里。

2配置

不写配置文件也能用 logq，但每次都要在命令里写日志路径。第一次使用时，建议运行下面的命令生成一份默认配置：

$ logq init
已创建配置文件：~/.config/logq/config.toml

配置文件用 TOML 格式。最常改的是“数据源”：给每组日志起一个名字，之后在命令里用 -s 名字 就能指定它。

~/.config/logq/config.toml

# 默认使用的数据源
default_source = "web"

# 输出格式：pretty（带颜色）、json、plain
output = "pretty"

# 时间显示的时区
timezone = "Asia/Shanghai"

[sources.web]
paths = ["/var/log/nginx/access.log*"]
format = "nginx"

[sources.api]
host = "deploy@10.0.3.12"           # 通过 SSH 读取远程日志
paths = ["/srv/api/logs/*.jsonl"]
format = "json"

常用配置项：

配置项默认值说明
default_source无命令里没写 -s 时使用的数据源
outputpretty输出到终端时的格式；接管道时会自动改成 plain
timezone系统时区解析和显示时间时使用的时区
formatauto日志格式，可选 nginx、json、syslog、auto
host无填写后通过 SSH 读取远程机器上的日志

配置写好后可以运行 logq config check，它会逐个检查数据源的路径是否存在、格式能否识别。

3常用命令

logq 的子命令不少，日常用得最多的是下面三个。所有命令都支持 --help 查看完整参数。

logq search：按条件搜索

在数据源里查找符合条件的日志行。条件可以是关键词，也可以是 字段=值 的形式；多个条件之间是“并且”的关系。

# 查找最近 1 小时内状态码为 500 的请求
$ logq search status=500 --since 1h

# 在 api 数据源里搜关键词 timeout，只看前 20 条
$ logq search -s api timeout --limit 20
参数说明
--since / --until时间范围，支持 30m、2h、2026-10-01 等写法
--limit最多返回多少条，默认 100
-s, --source指定数据源，覆盖配置里的 default_source

logq tail：实时跟踪

和 tail -f 类似，持续输出新写入的日志，但可以同时加过滤条件，还能一次跟踪多个文件。按 Ctrl + C 退出。

# 实时查看 web 数据源里的 4xx 和 5xx 请求
$ logq tail "status>=400"

# 跟踪远程 api 日志，并高亮 user_id 字段
$ logq tail -s api --highlight user_id

logq stats：快速统计

按某个字段分组计数，适合排查问题时先看个大概，比如哪个接口报错最多、哪个 IP 请求最频繁。

# 统计今天每个接口的 500 错误次数，取前 5 名
$ logq stats status=500 --by path --since today --top 5
PATH                 COUNT
/api/orders            412
/api/login              87
/api/upload             31
/api/search             12
/api/profile             4

加上 --output json 可以把结果交给其他脚本处理。
