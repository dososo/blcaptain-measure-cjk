# 中文排版规则（T 系列）

v0.1 基础档实现了 T01–T09、T11、T13。其余规则只列标题，说明在后续版本补全。

**严重级别：** error 会让校验失败；warn 只提示。

**基础档是近似判断：**
- 能算：浏览器默认样式、页面样式、`style` 属性、选择器优先级、继承、CSS 变量。
- `@media` 在桌面 1280px 和窄屏 390px 两个视口下分别求值。
- 也能处理：`@layer` 层级顺序、CSS 嵌套、`@supports not (…)`（视为不成立）、`font` 简写里的 `var()`。
- 不检查：隐藏元素（`hidden` 属性、`display: none`、`sr-only` 一类的类名）。**`aria-hidden="true"` 的文字仍然检查**：它只对读屏软件隐藏，页面上照样看得见。
- 不能算：其余 `@supports` 条件一律当作成立；不计算 `calc()`、`clamp()`。

> 本文件部分说明参考并改写自 W3C《中文排版需求》（Requirements for Chinese Text Layout，https://www.w3.org/TR/clreq/）中关于行首行尾禁则、标点符号排版、汉字与西文混排的内容。

<a id="t01"></a>
## T01 根元素声明中文 lang（error）

**为什么：** 浏览器根据 `lang` 选择字形、断行方式和回退字体。不写 `lang`，或者写成 `en`，中文可能用日文字形显示，标点的位置也会不对。

**怎么做：** `<html lang="zh-CN">`。繁体用 `zh-TW` 或 `zh-HK`，也可以用 `zh-Hans`、`zh-Hant` 这类写法。英文页面里的中文片段，在包住它的元素上写 `lang="zh-CN"` 也可以：校验器看的是每个中文元素实际继承到的语言。

<a id="t02"></a>
## T02 中英文、中文与数字之间要有间距（error）

**为什么：** 汉字和拉丁字母、数字直接挨在一起，读起来很挤，也难以分辨词的边界。

**两种做法，在 `measure.config.json` 的 `spacing` 里二选一：**
- `css`（网页默认）：引入 `measure.css`。它会显式写出 `text-autospace: normal`，由浏览器自动加间距，文案本身不用改。
  - 注意：Chrome 140、Firefox 145、Safari 18.4 的实现里，这个属性的初始值是 `no-autospace`，所以必须显式写出来。
  - 文本里已经有空格时，浏览器不会再额外加间距，两种做法混用也不会出现双倍间距。
  - 旧版浏览器没有这个属性，在那里显示不出间距。
- `text`：直接在文案里打空格，适合 Markdown、公众号，以及需要所有浏览器都显示间距的场景。

<a id="t03"></a>
## T03 中文用全角标点，引号风格统一（error）

**为什么：** 半角的 `, . ; : ? !` 夹在汉字中间，宽度不对，位置也偏，一眼就能看出是从英文输入法敲出来的。

**怎么做：**
- 中文语境用全角的 ，。；：？！
- 引号按配置统一：`quotes: "curly"`（默认，用 “”，与 GB/T 15834 一致）或 `quotes: "corner"`（用「」）。
- 不要用直引号 `"` 包裹中文。
- 英文句子、版本号（1.0.2）、比例（3:2）、代码里的标点不受这条规则约束。

<a id="t04"></a>
## T04 行首行尾禁则（error）

**为什么：** 逗号、句号这类标点出现在行首，是中文排版里最明显的错误之一。

**怎么做：** `line-break: strict`。这个属性广泛可用，`measure.css` 已经包含。

**完整档的判断方式：** 读取计算后的 `line-break`；同时逐个检查行首禁则里的标点（。，、；：？！、结束引号和括号等），如果它在某个宽度下实际排到了新一行的开头，就报 error，并在截图里框出那一段。

<a id="t05"></a>
## T05 正文行长 28–40 字（基础档 warn）

**为什么：** 一行太长，眼睛换行时容易找错位置；太短又会频繁换行。

**怎么做：** 正文容器加 `.measure-prose`（`max-width: 36em`），或者自己设置 `max-width`。

**基础档的判断方式：** 只能用「容器宽度 ÷ 字号」来估算，所以超过 40 字只报 warn。完整档实测超过 45 字才报 error。

**完整档的判断方式：** 在每个宽度下，把正文段落（`p`、`li`，15 个汉字以上，文字在行内子元素里也算）的文字按阅读顺序逐字归行，数每行有几个字。字包括汉字和全角标点（标点占一个字位），不包括西文字母、数字和空格。最长一行超过 45 个字报 error，超过 40 个字报 warn。多栏排版按每一栏的行长算。

<a id="t06"></a>
## T06 正文行高（error / warn）

**为什么：** 汉字是方块字，字面饱满，行距需要比英文更大。浏览器默认的 `normal` 大约是 1.2，对中文正文来说太密。

**怎么做：**
- 正文（`p`、`li`）用 1.6–1.9。
- 低于 1.5 报 error。
- 没有设置行高：30 个汉字以上的段落报 error（浏览器默认约 1.2）；更短的单行文字只报 warn。
- 在 1.5–1.6 之间或高于 1.9，报 warn。
- 标题建议 1.2–1.4。

<a id="t07"></a>
## T07 中文字距不能为负（error）

**为什么：** 英文标题常用负字距让字母更紧凑。汉字本身没有字间留白，再收紧就会挤在一起。

**怎么做：**
- 中文字距用 0 到 0.05em。
- 不要把 Tailwind 的 `tracking-tight`、`tracking-tighter` 用在中文上。
- 只包含西文的元素不受这条规则约束。

<a id="t08"></a>
## T08 中文不用斜体（error）

**为什么：** 中文字体没有斜体字面，浏览器只能把字形硬掰歪，非常难看。

**怎么做：**
- 强调用着重号 `text-emphasis: dot`，现在已经不需要 `-webkit-` 前缀。中文要写 `text-emphasis-position: under right`，`measure.css` 已经包含。
- 也可以用加粗，或者换成楷体。
- `<em>`、`<i>`、`<cite>` 在浏览器里默认是斜体。引入 `measure.css` 之后，`font-synthesis-style: none` 会让其中的中文保持正体，西文的真斜体不受影响。
- 页面上显式写了 `font-style: italic` 的中文，仍然报 error。
- 代码块（`pre`、`code` 等）里的斜体中文注释只报 warn：这是代码高亮的常见写法，但仍然建议注释改用正体。

<a id="t09"></a>
## T09 text-transform、small-caps 对汉字无效（warn）

**为什么：** 这类样式通常是照搬了英文设计，用在中文上没有效果，说明样式没有为中文调整过。

**怎么做：** 只把它们用在纯西文的元素上，比如英文眉标。

<a id="t11"></a>
## T11 最小字号（error / warn）

**为什么：** 汉字笔画多，字号太小时笔画会糊成一团。

**怎么做：**
- 任何中文都不小于 12px，否则报 error。
- 正文（`p`、`li`）不小于 14px，否则报 warn。

<a id="t12"></a>
## T12 首行缩进和段间距二选一（warn，只有完整档检查）

**为什么：** 首行缩进和段间距都是用来分段的，两个一起用，段落之间就分得过头，版面松散。

**怎么做：** 二选一。要么 `text-indent: 2em` 加 `margin: 0`（书刊风格），要么不缩进、只用段间距（网页常见）。

**完整档的判断方式：** 相邻的两个正文段落 `p`，前一段有首行缩进，同时两段之间的空隙大于 0.25 个字高，就报 warn。浏览器给 `p` 的默认上下边距是 1em，所以只写了 `text-indent` 却没有把 `margin` 清零，也会命中。

<a id="t13"></a>
## T13 字体栈里要有中文字体（error）

**为什么：** 字体栈里没有中文字体时，中文会回退到访客系统的默认字体，具体是哪一款由操作系统和浏览器决定，效果不可控。

**怎么做：** 先写西文字体，再写中文字体，最后写通用族。例如：

```css
font-family: "Inter", "PingFang SC", "Noto Sans SC", "Microsoft YaHei", sans-serif;
```

代码块（`pre`、`code`、`kbd`、`samp`）里的中文只报 warn：等宽字体栈不列中文字体是常规做法，但中文仍会回退到系统字体，可以在等宽字体后面补一个中文字体。

字体能不能用、怎么用，见 `fonts.md`。

<a id="t14"></a>
## T14 标点挤压 text-spacing-trim（P1）

**现状：** 只有 Chrome 和 Edge 123 及以上支持，并且依赖字体带 `halt` 或 `chws` 特性。它的初始值在支持的浏览器里本来就会生效，所以 `measure.css` 不写这个属性。

<a id="t15"></a>
## T15 text-wrap: balance / pretty（P1）

**现状：** Firefox 不支持 `pretty`；`balance` 在 Chromium 里只平衡 6 行以内的文本；两者对中文的实际效果还没有实测，暂不推荐。
