用户 API 文档

通过本 API 可以查询、创建和更新用户。所有请求与响应均使用 JSON，字符编码为 UTF-8，时间字段采用 ISO 8601（UTC）格式。

Base URLhttps://api.example.com/v1

鉴权方式

API 使用 Bearer Token 鉴权。先用控制台中生成的 client_id 与 client_secret 换取访问令牌（access token），之后每个请求都需在 Authorization 请求头中携带该令牌。

1. 获取访问令牌

请求

POST /v1/oauth/token
Content-Type: application/json

{
  "grant_type": "client_credentials",
  "client_id": "cli_8f2a91c0",
  "client_secret": "sk_live_xxxxxxxxxxxxxxxx",
  "scope": "users:read users:write"
}

响应 200

{
  "access_token": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "Bearer",
  "expires_in": 7200,
  "scope": "users:read users:write"
}

2. 在请求中携带令牌

curl https://api.example.com/v1/users \
  -H "Authorization: Bearer eyJhbGciOiJSUzI1NiIs..."

权限范围（scope）

Scope说明
users:read读取用户列表与用户详情
users:write创建、更新用户（不隐含读取权限）
令牌有效期为 2 小时（expires_in 单位为秒），过期后需重新获取。client_secret 只能在服务端使用，切勿写入前端代码或提交到代码仓库。

错误响应

请求失败时返回对应的 HTTP 状态码，响应体格式统一如下：

{
  "error": {
    "code": "invalid_token",
    "message": "访问令牌已过期",
    "request_id": "req_5d1e7a"
  }
}
状态码code含义
400invalid_request参数缺失或格式错误
401invalid_token未携带令牌，或令牌无效、已过期
403insufficient_scope令牌缺少该接口所需的 scope
404not_found资源不存在
409conflict资源冲突，例如邮箱已被注册
429rate_limited请求过于频繁，请参考 Retry-After 头重试
500internal_error服务端错误，请携带 request_id 联系支持

用户接口

以下四个接口都操作同一个用户对象：

字段类型说明
idstring用户唯一 ID，以 usr_ 开头
namestring显示名称
emailstring邮箱，全局唯一
rolestringadmin | member | viewer
statusstringactive | disabled
created_atstring创建时间
updated_atstring最后更新时间

获取用户列表

GET/users需要 users:read

分页返回用户，按创建时间倒序排列。

查询参数

参数类型说明
pageinteger页码，从 1 开始，默认 1
page_sizeinteger每页条数，1–100，默认 20
statusstring按状态筛选：active 或 disabled
qstring按名称或邮箱模糊搜索

请求示例

curl "https://api.example.com/v1/users?page=1&page_size=2&status=active" \
  -H "Authorization: Bearer $TOKEN"

响应 200

{
  "data": [
    {
      "id": "usr_01HZX3",
      "name": "张三",
      "email": "zhangsan@example.com",
      "role": "admin",
      "status": "active",
      "created_at": "2026-09-12T08:30:00Z",
      "updated_at": "2026-10-01T02:15:00Z"
    },
    {
      "id": "usr_01HZW9",
      "name": "李四",
      "email": "lisi@example.com",
      "role": "member",
      "status": "active",
      "created_at": "2026-09-10T03:12:00Z",
      "updated_at": "2026-09-10T03:12:00Z"
    }
  ],
  "pagination": { "page": 1, "page_size": 2, "total": 37 }
}

获取单个用户

GET/users/{id}需要 users:read

根据用户 ID 返回用户详情。用户不存在时返回 404。

路径参数

参数类型说明
id必填string用户 ID

请求示例

curl https://api.example.com/v1/users/usr_01HZX3 \
  -H "Authorization: Bearer $TOKEN"

响应 200

{
  "id": "usr_01HZX3",
  "name": "张三",
  "email": "zhangsan@example.com",
  "role": "admin",
  "status": "active",
  "created_at": "2026-09-12T08:30:00Z",
  "updated_at": "2026-10-01T02:15:00Z"
}

创建用户

POST/users需要 users:write

创建一个新用户，成功返回 201 和完整用户对象。邮箱已存在时返回 409。

请求体

字段类型说明
name必填string1–64 个字符
email必填string合法邮箱地址
rolestring默认 member

请求示例

curl -X POST https://api.example.com/v1/users \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "王五",
    "email": "wangwu@example.com",
    "role": "viewer"
  }'

响应 201

{
  "id": "usr_01HZY7",
  "name": "王五",
  "email": "wangwu@example.com",
  "role": "viewer",
  "status": "active",
  "created_at": "2026-10-25T06:00:00Z",
  "updated_at": "2026-10-25T06:00:00Z"
}

更新用户

PATCH/users/{id}需要 users:write

部分更新：只修改请求体中出现的字段，未出现的字段保持不变。返回更新后的用户对象。

路径参数

参数类型说明
id必填string用户 ID

请求体（至少包含一个字段）

字段类型说明
namestring1–64 个字符
emailstring新邮箱，不能与其他用户重复
rolestringadmin | member | viewer
statusstring设为 disabled 可停用用户

请求示例

curl -X PATCH https://api.example.com/v1/users/usr_01HZY7 \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "role": "member" }'

响应 200

{
  "id": "usr_01HZY7",
  "name": "王五",
  "email": "wangwu@example.com",
  "role": "member",
  "status": "active",
  "created_at": "2026-10-25T06:00:00Z",
  "updated_at": "2026-10-25T07:42:10Z"
}
