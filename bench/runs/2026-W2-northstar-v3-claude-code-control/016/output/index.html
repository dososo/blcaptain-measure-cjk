Skiff 快速上手

Skiff 是一个开源的命令行工具，用一份配置文件管理项目脚手架、任务脚本和远程目录同步。本指南带你在 5 分钟内完成安装、配置，并掌握三个最常用的命令。

MIT 许可证 macOS / Linux / Windows 单文件二进制，无运行时依赖

第 1 步安装

选择适合你系统的安装方式。所有方式安装的都是同一个独立二进制文件。

$ brew install skiff
$ curl -fsSL https://get.skiff.dev/install.sh | sh

脚本默认安装到 ~/.local/bin，可通过 SKIFF_INSTALL_DIR 环境变量修改。

> scoop install skiff
$ git clone https://github.com/skiff-cli/skiff.git
$ cd skiff
$ make install

需要 Go 1.22 或更高版本。

安装完成后，验证版本：

$ skiff --version
skiff 1.4.2 (darwin/arm64)
如果提示 command not found，请确认安装目录已加入 PATH，然后重新打开终端。

第 2 步配置

Skiff 按以下顺序读取配置，后者覆盖前者：

  1. 全局配置：~/.config/skiff/config.toml
  2. 项目配置：项目根目录下的 skiff.toml
  3. 环境变量：以 SKIFF_ 开头，例如 SKIFF_LOG_LEVEL=debug
  4. 命令行参数：例如 --profile staging

最小项目配置

在项目根目录创建 skiff.toml：

skiff.toml
# 项目基本信息
[project]
name = "my-app"

# 任务：用 skiff run <名称> 执行
[tasks]
dev   = "npm run dev"
test  = "npm test -- --coverage"
build = { cmd = "npm run build", depends = ["test"] }

# 同步目标：用 skiff sync <名称> 执行
[sync.staging]
host    = "deploy@staging.example.com"
path    = "/srv/my-app"
include = ["dist/**", "package.json"]
exclude = ["*.map"]

常用配置项

配置项默认值说明
log_level"info"日志级别：debug / info / warn / error
shell系统默认执行任务时使用的 shell，如 "bash"、"pwsh"
parallel4任务并行执行的最大数量
env_file".env"运行任务前自动加载的环境变量文件

随时可以检查最终生效的配置：

$ skiff config show

第 3 步三个常用命令

skiff init — 初始化项目

在当前目录生成 skiff.toml，并根据检测到的项目类型（Node、Python、Go 等）预填常用任务。

$ skiff init
✓ 检测到 Node.js 项目 (package.json)
✓ 已创建 skiff.toml，包含 3 个任务：dev, test, build
参数说明
--template <名称>使用指定模板，如 node、python、blank
--force覆盖已存在的 skiff.toml

skiff run — 执行任务

运行配置中定义的任务。依赖任务会自动先执行；不带参数时列出所有可用任务。

$ skiff run build
▸ test   npm test -- --coverage
✓ test   完成 (4.2s)
▸ build  npm run build
✓ build  完成 (11.8s)
参数说明
--watch监听文件变化，自动重新执行
--no-deps跳过依赖任务，只执行指定任务
-- <参数...>把后续参数原样传给任务命令，如 skiff run test -- --bail

skiff sync — 同步到远程

按 [sync.<名称>] 中的规则，把本地文件增量同步到远程主机（基于 SSH）。

$ skiff sync staging --dry-run
将上传 12 个文件 (3.4 MB)，删除 0 个文件
$ skiff sync staging
✓ 已同步到 deploy@staging.example.com:/srv/my-app (2.1s)
参数说明
--dry-run只显示将要变更的文件，不实际传输
--delete删除远程存在但本地已不存在的文件
首次同步到新目标前，建议先加 --dry-run 确认文件列表，尤其是使用 --delete 时。

下一步

  • 运行 skiff help <命令> 查看任意命令的完整参数。
  • 运行 skiff completion zsh（或 bash / fish / pwsh）生成 shell 自动补全脚本。
  • 遇到问题？用 SKIFF_LOG_LEVEL=debug 重新执行命令，并附上输出提交 Issue。
