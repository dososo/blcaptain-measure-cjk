用简洁的接口，连接你的用户。
通过 REST API 获取、创建、更新和删除用户，轻松集成到你的应用中。

REST 架构JSON 格式HTTPS 安全传输
BASE URLhttps://api.folio.example/v1

身份鉴权 #

所有接口均使用 Bearer Token 进行身份验证。请在每次请求的 Authorization 请求头中携带你的 API Token。

REQUEST HEADER 
Authorization: Bearer YOUR_API_TOKEN

JSON 请求需同时设置 Content-Type: application/json。Token 缺失、失效或过期时，接口返回 401 Unauthorized；权限不足时返回 403 Forbidden。

妥善保管你的 Token
在服务端通过环境变量读取 Token，避免将其暴露在前端代码、公开仓库或请求 URL 中。

用户接口

4 ENDPOINTS

管理用户的完整生命周期。所有时间字段均采用 UTC / ISO 8601 格式。

没有找到匹配的接口，请尝试搜索“获取”或“POST”。

GET/users/{id}获取用户

根据用户 ID 获取单个用户的详细信息。需要 users:read 权限。

路径参数 PATH PARAMETERS

参数类型说明
id *string必填，用户唯一 ID
响应示例 ● 200 OK
{
  "data": {
    "id": "usr_8f2a1b",
    "name": "林一",
    "email": "linyi@example.com",
    "created_at": "2026-01-15T08:30:00Z",
    "updated_at": "2026-01-15T08:30:00Z"
  }
}

用户不存在时返回 404 user_not_found。

POST/users创建用户

创建新用户。需要 users:write 权限，电子邮箱必须唯一。

请求体 APPLICATION/JSON

参数类型说明
name *string必填，1–80 个字符
email *string必填，有效邮箱，最多 254 个字符

请求示例

{
  "name": "林一",
  "email": "linyi@example.com"
}
响应示例 ● 201 Created
{
  "data": {
    "id": "usr_8f2a1b",
    "name": "林一",
    "email": "linyi@example.com",
    "created_at": "2026-01-15T08:30:00Z",
    "updated_at": "2026-01-15T08:30:00Z"
  }
}

邮箱已存在时返回 409 email_already_exists。参数校验失败时返回 422 validation_error。

PATCH/users/{id}更新用户

更新指定用户的信息。需要 users:write 权限；仅修改提供的字段，其他字段保持不变。

路径参数

参数类型说明
id *string必填，用户唯一 ID

请求体 至少提供一个字段，不接受 null

参数类型说明
namestring可选，1–80 个字符
emailstring可选，有效且唯一的邮箱，最多 254 个字符

请求示例

{ "name": "林一 Lin" }
响应示例 ● 200 OK
{
  "data": {
    "id": "usr_8f2a1b",
    "name": "林一 Lin",
    "email": "linyi@example.com",
    "created_at": "2026-01-15T08:30:00Z",
    "updated_at": "2026-01-16T09:00:00Z"
  }
}

可能返回 404 user_not_found、409 email_already_exists 或 422 validation_error。

DELETE/users/{id}删除用户

永久删除指定用户，此操作不可撤销。需要 users:delete 权限。

路径参数

参数类型说明
id *string必填，用户唯一 ID

请求示例 无请求体

DELETE /v1/users/usr_8f2a1b
Authorization: Bearer YOUR_API_TOKEN
响应示例 ● 204 No Content
HTTP/1.1 204 No Content

成功时无响应体，请勿解析 JSON。用户不存在或重复删除时返回 404 user_not_found。

状态码与错误

通过 HTTP 状态码判断请求结果；错误响应提供稳定的错误代码和可读说明。

400bad_request · 请求格式错误或 JSON 无效
401 / 403unauthorized / forbidden · 鉴权失败或权限不足
404user_not_found · 用户不存在
409email_already_exists · 邮箱已被使用
422validation_error · 字段校验失败
429rate_limit_exceeded · 请求频率超限
500internal_error · 服务内部错误

错误响应示例

{
  "error": {
    "code": "user_not_found",
    "message": "指定的用户不存在。"
  },
  "request_id": "req_a7c921"
}

请求限制

每个 Token 每分钟最多发送 60 次请求。超出后返回 429，请根据 Retry-After 响应头中指定的秒数等待后重试。
