用户 API

稳定版本

连接你的应用与用户。通过简洁、一致的 REST 接口，
轻松完成用户的查询、创建与更新。

RESTful APIJSON 格式HTTPS 传输
BASE URLhttps://api.mosaic.example/v1
所有接口均需鉴权，时间字段采用 UTC · ISO 8601 格式。浏览全部接口 ↓

鉴权方式

01

API 使用 Bearer Token 进行身份验证。每次请求时，请在 HTTP 请求头中携带访问令牌。

请求头Authorization: Bearer <YOUR_API_TOKEN>
妥善保管你的 Token

请通过服务端环境变量保存令牌，避免将其暴露在浏览器代码或公开仓库中。

示例以已签发的 Token 为前提；缺失、无效或过期的令牌将返回 401 Unauthorized。

⌘ 鉴权请求示例
curl --request GET \
  'https://api.mosaic.example/v1/users' \
  --header 'Authorization: Bearer YOUR_API_TOKEN' \
  --header 'Accept: application/json'
所有接口均使用相同的鉴权方式

USERS / 01

获取用户列表

#

分页获取工作空间中的用户，默认按创建时间倒序排列。

GET/users权限：users:read

查询参数

pageinteger可选

页码，从 1 开始；默认值为 1。

per_pageinteger可选

每页数量，取值 1–100；默认值为 20。

响应说明 200 OK

data 为用户对象数组；pagination 包含当前页码、每页数量与总记录数。

用户对象

id 为唯一标识，name 为名称，email 为邮箱；以上字段均为字符串。created_at 与 updated_at 为 UTC 时间字符串。

可能的错误：400、401、403、429、500。

curl --request GET \
  'https://api.mosaic.example/v1/users?page=1&per_page=20' \
  --header 'Authorization: Bearer YOUR_API_TOKEN' \
  --header 'Accept: application/json'
响应示例200 OK
{
  "data": [
    {
      "id": "usr_01J8QX",
      "name": "林小满",
      "email": "xiaoman@example.com",
      "created_at": "2026-01-15T08:30:00Z",
      "updated_at": "2026-01-15T08:30:00Z"
    }
  ],
  "pagination": {
    "page": 1,
    "per_page": 20,
    "total": 1
  }
}
USERS / 02

获取用户详情

#

通过唯一用户 ID 获取用户的基本信息及创建、更新时间。

GET/users/{user_id}权限：users:read

路径参数

user_idstring必填

用户的唯一标识，例如 usr_01J8QX。

响应说明 200 OK

返回完整用户对象。未找到对应用户时返回 404。

用户对象

id 为唯一标识，name 为名称，email 为邮箱；以上字段均为字符串。created_at 与 updated_at 为 UTC 时间字符串。

可能的错误：401、403、404、429、500。

curl --request GET \
  'https://api.mosaic.example/v1/users/usr_01J8QX' \
  --header 'Authorization: Bearer YOUR_API_TOKEN' \
  --header 'Accept: application/json'
响应示例200 OK
{
  "id": "usr_01J8QX",
  "name": "林小满",
  "email": "xiaoman@example.com",
  "created_at": "2026-01-15T08:30:00Z",
  "updated_at": "2026-01-15T08:30:00Z"
}
USERS / 03

创建用户

#

在工作空间中创建一位新用户。邮箱地址须唯一，用户 ID 由系统生成。

POST/users权限：users:write

请求体 · application/json

namestring必填

用户名称，去除首尾空白后为 1–50 个字符。

emailstring必填

有效的邮箱地址，最长 254 个字符。

不接受 null 值及未知字段。

响应说明 201 Created

返回新建的用户对象。邮箱已被使用时返回 409。

用户对象

id 为唯一标识，name 为名称，email 为邮箱；以上字段均为字符串。created_at 与 updated_at 为 UTC 时间字符串。

可能的错误：400、401、403、409、429、500。

curl --request POST \
  'https://api.mosaic.example/v1/users' \
  --header 'Authorization: Bearer YOUR_API_TOKEN' \
  --header 'Accept: application/json' \
  --header 'Content-Type: application/json' \
  --data '{"name":"林小满","email":"xiaoman@example.com"}'
响应示例201 Created
{
  "id": "usr_01J8QX",
  "name": "林小满",
  "email": "xiaoman@example.com",
  "created_at": "2026-01-15T08:30:00Z",
  "updated_at": "2026-01-15T08:30:00Z"
}
USERS / 04

更新用户

#

更新指定用户的部分信息。仅修改提交的字段，未提交的字段保持原值。

PATCH/users/{user_id}权限：users:write

路径参数

user_id必填

用户的唯一标识，类型为 string。

请求体 · application/json

namestring可选

用户名称，去除首尾空白后为 1–50 个字符。

emailstring可选

有效且唯一的邮箱地址，最长 254 个字符。

至少提交一个字段；不接受 null 值及未知字段。

响应说明 200 OK

返回更新后的完整用户对象，updated_at 同步更新。

用户对象

id 为唯一标识，name 为名称，email 为邮箱；以上字段均为字符串。created_at 与 updated_at 为 UTC 时间字符串。

可能的错误：400、401、403、404、409、429、500。

curl --request PATCH \
  'https://api.mosaic.example/v1/users/usr_01J8QX' \
  --header 'Authorization: Bearer YOUR_API_TOKEN' \
  --header 'Accept: application/json' \
  --header 'Content-Type: application/json' \
  --data '{"name":"林小满同学"}'
响应示例200 OK
{
  "id": "usr_01J8QX",
  "name": "林小满同学",
  "email": "xiaoman@example.com",
  "created_at": "2026-01-15T08:30:00Z",
  "updated_at": "2026-01-16T10:00:00Z"
}
!

错误与状态码

03

成功响应直接返回资源。错误响应采用统一结构；使用 request_id 关联服务端日志，便于排查请求。

状态码含义与处理方式
400请求参数无效，请检查字段与取值范围。
401鉴权失败，请检查或更换 Token。
403权限不足，请确认令牌具备对应权限。
404用户不存在，请核对用户 ID。
409邮箱已被使用，请更换邮箱。
429请求过于频繁，按 Retry-After 秒数重试。
500服务异常，请稍后重试。
错误响应示例401 Unauthorized
{
  "error": {
    "code": "unauthorized",
    "message": "Invalid or expired token"
  },
  "request_id": "req_8f3b2a"
}
