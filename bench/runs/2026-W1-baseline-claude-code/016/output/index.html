快速上手

sumi 墨

一个把 Markdown 目录编译成静态网站的开源命令行工具。单个二进制文件，没有运行时依赖，五分钟内跑通第一个站点。

版本 0.9.2Apache-2.0macOS · Linux · Windows

一

安装

任选一种方式。三种方式装出来的是同一个二进制文件。

Homebrew（macOS / Linux）

$ brew install sumi

Cargo（需要 Rust 1.75+）

$ cargo install sumi-cli --locked

预编译二进制

从 GitHub Releases 页面下载对应平台的压缩包，解压后把 sumi 放进 PATH 里的任一目录即可。下载后建议用同页的 SHA256SUMS 文件校验：

$ shasum -a 256 -c SHA256SUMS --ignore-missing

确认安装成功

$ sumi --version
sumi 0.9.2
二

配置

sumi 读取项目根目录下的 sumi.toml。没有这个文件时全部使用默认值，所以配置是可选的。最小可用配置如下：

sumi.toml 
schema_version = "1"

[site]
title    = "我的笔记"
base_url = "https://example.com"
language = "zh-CN"

[build]
source = "content"   # Markdown 所在目录
output = "public"    # 生成的静态文件目录
drafts = false       # 是否输出 draft: true 的文章

常用字段

字段默认值说明
site.title目录名站点标题，出现在页面 <title> 与页头
site.base_url/部署后的根地址，用于生成绝对链接与 sitemap
build.sourcecontentMarkdown 源文件目录
build.outputpublic构建产物目录，每次构建前会被清空
build.draftsfalse是否包含草稿

环境变量覆盖

任何字段都可以用 SUMI_ 前缀的环境变量临时覆盖，层级用双下划线连接。适合在 CI 里切换部署地址：

$ SUMI_SITE__BASE_URL=https://staging.example.com sumi build
优先级：命令行参数 > 环境变量 > sumi.toml > 内置默认值。
三

常用命令

日常使用基本只需要下面三个命令。完整列表见 sumi help。

sumi init — 新建项目

在指定目录生成项目骨架：一份 sumi.toml、一个 content/ 目录和一篇示例文章。目标目录非空时会拒绝执行，不会覆盖已有文件。

$ sumi init my-notes
created  my-notes/sumi.toml
created  my-notes/content/hello.md
done. next: cd my-notes && sumi serve

sumi serve — 本地预览

启动本地预览服务器，监听文件变化并自动刷新浏览器。默认只绑定 127.0.0.1，不会暴露到局域网。

$ sumi serve --port 4000 --drafts
watching content/ …
serving  http://127.0.0.1:4000
参数说明
--port <n>端口号，默认 3000
--drafts预览时包含草稿
--open启动后自动打开浏览器

sumi build — 构建发布

把 content/ 编译到 public/。产物是纯静态文件，可直接上传到任何静态托管服务。

$ sumi build --minify
built 42 pages in 0.31s → public/
参数说明
--minify压缩 HTML / CSS 输出
--output <dir>覆盖 build.output
--strict遇到失效内链时以非零状态退出，适合放进 CI
四

下一步

  1. 在 content/ 里写下第一篇文章，文件头用 YAML front matter 填 title 与 date。
  2. 运行 sumi serve 边写边看。
  3. 满意后 sumi build --strict，把 public/ 部署出去。

遇到问题，先运行 sumi doctor 检查环境与配置，再到项目仓库提 issue。

sumi 为本文档的示例工具，命令与参数仅作版式演示。
